# Идеи и планы (backlog)

Здесь собраны идеи, которые нужно реализовать. Порядок отражает приоритет: сначала
дешёвые и полезные вещи, потом крупные. Основной план по этапам — в
[ROADMAP.md](ROADMAP.md).

### Уровень 2: полезная аналитика (3–5 дней)

- [ ] **Перенос настроек из ILSpy/dnSpy**: при переносе фич тащить и их настройки
      (ILSpy: `%APPDATA%\ICSharpCode\ILSpy.xml`; dnSpy: `%APPDATA%\dnSpy\*.xml`),
      маппить совпадающие ключи в `AppSettings`, неизвестные складывать в раздел
      «Imported (read-only)». Плюс импорт/экспорт `.ilxp-settings` для переноса между
      машинами.
- [ ] **Больше своих настроек**: тема (светлая/тёмная), шрифт редактора и размер,
      показывать IL-комментарии, автораскрытие дерева при загрузке, лимит истории
      навигации, формат логов, «спрашивать перед очисткой».
- [x] **Health report сборки** (`--health`, `Edit → Assembly health…`): PE-факты (machine,
      секции, энтропия, timestamp с пометкой deterministic build, CLR header, CorFlags,
      strong name), количество типов/методов/полей/ресурсов/атрибутов, резолв **всех**
      зависимостей с путями, общий балл 0–100 и вердикт.
- [x] **Fingerprint обфускатора** (`ObfuscatorFingerprint`): сигнатуры Confuser/ConfuserEx,
      .NET Reactor, Eazfuscator, SmartAssembly, Dotfuscator, Babel, Crypto Obfuscator,
      Agile.NET/SecureTeam, Xenocode, ILProtector, MaxtoCode, Goliath, Skater, CodeWall,
      Spices.NET, MPRESS, UPX, Themida + общие индикаторы (имена, энтропия, NOP-плотность,
      base64-литералы, proxy-методы). Каждый кандидат со score и списком улик.
      Проверено: чистая сборка 8/100, обфусцированная нашим обфускатором 56/100.
- [x] **Diff двух версий** (`--diff`, `File → Compare versions…`): идентичность метаданных +
      хеш IL (FNV-1a), не зависит от смещения оффсетов и целей ветвлений, показывает
      added/removed/changed с деталями «body added/removed/differs».
- [x] **Preservation bundle** (`--bundle`, `File → Export preservation bundle…`): оригинальные
      байты + PDB, IL-листинг, декомпиляция в IL/C#/VB, ресурсы, health-отчёт и manifest
      с SHA-256 каждого файла — data-hoarding экспорт «всё в одной папке».
- [x] **Call graph explorer** (`--callgraph`, `Edit → Call graph…`): fan-out (кто больше всех
      вызывает), fan-in (самые «горячие» методы), «сироты» без внутренних вызовов, циклы
      рекурсии (Tarjan, итеративный — без переполнения стека), счётчик внешних ссылок.
      На ILXP.exe: 4178 методов, 8090 внутренних вызовов, 25 циклов.
- [x] **Fixpoint-тест** (`--fixpoint [--iterations n]`): decompile → managed ilasm →
      decompile → сравнить с оригиналом. Даёт честную цифру потерь. Доведено до
      **100 % по членам и 100 % по телам** (4077 из 4077 методов совпадают вместе с
      таблицами обработчиков), на `System.Core.dll` — 99.99 % / 98.15 %; 3 итерации подряд
      дают стабильный результат. Что для этого пришлось доделать в ассемблере:
      `.property`/`.event`, вложенные типы, `implements`, generic-типы и generic-методы,
      P/Invoke, данные статических полей (`.data … at I_xxxx`), точку входа,
      scope-префиксы `[System.Core]`, public key token в `.assembly extern`.
- [x] **Exception handlers в ассемблере**: `.try` / `catch` / `finally` / `filter` / `fault`
      выводятся блоками и восстанавливаются в таблицу обработчиков (753 защищённых региона
      на ILXP.exe), плюс `.override` (явные реализации интерфейсов), `native int`,
      `[.module]` для forward-ссылок и `.assembly extern` с public key token.
      `--fixpoint` теперь хеширует и таблицу обработчиков, а не только инструкции —
      **100 % по членам и 100 % по телам** (4012 из 4012), на `System.Core.dll` 99.99 % / 98.15 %.
- [x] **Запускаемая пересборка для обычного кода**: маленькие программы с лямбдами, LINQ,
      generic-делегатами, switch, try/catch/finally, foreach по `List<T>` и вложенными
      generic-типами (`Bag<T>.Enumerator`) после `--ildasm` → `--ilasm` работают.
- [x] **Верификатор тел** (`--ilverify`, а также в `--fixpoint`): симуляция стека по каждой
      инструкции — underflow, глубина против `.maxstack`, непустой стек на `ret`, диапазоны
      коротких форм (`ldarg.s`, `br.s`), корректность `switch`, границы try/handler/filter.
      Калиброван на реальных сборках: 0 находок в mscorlib (25 337 тел), System (16 389),
      System.Core (7 852), System.Xml (12 251) — поэтому его отчёту можно верить.
      На пересобранной сборке он сразу назвал методы, которые текстово совпадали, но были невалидны.
- [x] **Остаток `PEVerify` для пересборки ILXP.exe**: 437 → 204 → **4**, и эти 4 —
      те же самые, что у оригинала (unmanaged pointer в `WaterLogo`). Пересобранный
      `ilxp.exe` запускает GUI и декомпилирует чужие сборки со 100 % accuracy.
      Что для этого понадобилось: публичный ключ в `.assembly extern` применяется и к
      ссылкам, созданным предобъявлением типов, двухфазное предобъявление (сначала скелеты,
      потом базовые типы и интерфейсы), `modreq`/`modopt`, `constrained.` с реальными
      constraint'ами (`.constraint`, `.gpflags`), арность member ref только из параметров
      (а не из аргументов объемлющего типа) и предпочтение MethodDef вместо MemberRef.
- [x] **Запускаемая пересборка самого ILXP.exe**: `--ildasm` → `--ilasm` даёт рабочий
      `ilxp.exe`; в тестах есть сквозная проверка «пересобранный инструмент читает сборку».
- [ ] **Timeline версий**: найти в папке одноимённые сборки разных версий и показать рядом.
